# 私隱政策（QDiary）

- 應用程式名稱：QDiary
- 開發者：frog-im
- 聯絡方式：[g.ns.0700g@gmail.com](mailto:g.ns.0700g@gmail.com)
- 生效日期：2026-04-19
- 最後更新日期：2026-04-19

本私隱政策是根據 QDiary 應用程式目前的實作情況編寫。QDiary 提供日記撰寫、任務生成與回顧、登入、手動雲端儲存、廣告及通知等功能，並在此過程中，於必要範圍內處理個人資料或可能構成個人資料的相關資訊。

## 1. 提供的功能

QDiary 提供以下功能：

- 日記的撰寫、編輯及查看
- 分類管理及日曆檢視
- 任務生成、任務回顧及任務完成處理
- 本地日記應用程式鎖定及本地加密
- 電郵登入、電郵驗證、匿名（訪客）登入及密碼重設
- 由使用者主動執行的雲端儲存及讀取
- 廣告顯示及廣告私隱選項處理
- 任務提醒通知

## 2. 處理的資料類別

### 2-1. 使用者直接輸入的資料

- 電郵地址
- 密碼
- 日記標題、內文、日期、分類及難度
- 任務回應、回顧內容及所選任務資訊
- 與任務設定檔有關的選項及摘要文字
- 用於日記應用程式鎖定的密碼短語

### 2-2. 應用程式儲存在裝置中的資料

- 本地日記資料庫（SQLite）
- 本地日記的任務狀態資料
- 出席、設定、語言、通知及廣告相關狀態值
- 應用程式鎖定驗證值、salt 及加密中繼資料
- 任務通知排程資料

### 2-3. 帳戶及識別資料

透過 Firebase Authentication，可能會處理以下資料：

- Firebase UID
- 電郵地址
- 電郵驗證是否完成
- 是否使用匿名登入

### 2-4. 廣告及同意處理資料

在使用 Google AdMob 及 UMP SDK 時，可能會處理以下資料：

- 廣告識別碼（例如 Android AD_ID）
- IP 位址及網絡資料
- 裝置資料、作業系統版本及應用程式資料
- 廣告展示、點擊及獎勵處理資料
- 廣告同意狀態及私隱選項狀態

### 2-5. 通知相關資料

- 是否已授予通知權限
- 含有進行中任務的日記識別值
- 任務通知文字
- 已排程的通知時間

## 3. 處理目的

本應用程式基於以下目的處理資料：

- 註冊、登入、電郵驗證及密碼重設
- 日記撰寫、儲存及查看
- 任務生成、回顧及完成判定
- 與應用程式鎖定相關的本地加密及解密
- 處理使用者要求的雲端儲存及讀取
- 提供任務通知
- 提供廣告、處理廣告獎勵及反映廣告同意狀態
- 安全保障、錯誤處理及服務營運

## 4. 本地儲存、雲端儲存及外部處理

### 4-1. 本地儲存

日記及任務資料原則上儲存在裝置的本地資料庫中。

- 未啟用應用程式鎖定時：以一般形式作本地儲存
- 啟用應用程式鎖定時：部分資料（例如日記標題、內文及任務狀態）可能會在本地加密後儲存

### 4-2. 雲端儲存

本應用程式僅在使用者主動執行 `Save` 功能時，才會將資料儲存至 Firebase Firestore。

根據目前專案設定：

- 不使用自動完整同步
- 只有在使用者手動儲存時，資料才會儲存至 Firestore `savedDiaries`
- 儲存時，日記標題、內文及任務狀態可能會根據目前應用程式鎖定狀態，以加密形式儲存
- 只有在使用者執行 `Load` 時，才會將 Firestore 中的儲存資料重新載入至本地

### 4-3. 任務生成及回顧時的外部處理

當使用者要求生成任務或進行回顧時，以下資料可能會透過 Firebase Functions 用於外部處理：

- 日記標題
- 日記內文或回顧內文
- 分類
- 難度
- 所選任務
- 任務設定檔摘要資料

上述資料將用於透過 OpenAI API 進行任務生成及評估。

重要說明：

- 只有在使用任務功能時，相關日記內容才會用於外部處理。
- 根據目前專案設定，不使用將任務記錄儲存至獨立 `questLogs` 集合中的程式碼。

## 7. 保存及使用期間

本應用程式按以下標準保存資料：

- 本地日記／設定資料：直至使用者刪除或解除安裝應用程式為止
- Firebase 帳戶資料：於使用者維持帳戶期間
- Firestore 儲存資料：於使用者持續保留已儲存項目期間
- 任務請求處理資料：於無伺服器處理所需範圍內
- 廣告／同意相關資料：依各外部服務供應商之政策而定

此外，目前專案尚包含以下自動清理邏輯：

- 於一段時間後清理匿名使用者帳戶及其下屬 Firestore 資料
- 清理長時間不活躍的一般使用者帳戶及其下屬 Firestore 資料

但上述邏輯是否實際套用於正式營運環境，仍可能因部署狀態及伺服器設定而有所不同。

## 8. 應用程式鎖定及本地加密說明

本應用程式提供獨立的 `Diary App Lock` 功能。

- 應用程式鎖定用密碼短語與帳戶密碼彼此獨立。
- 應用程式鎖定用密碼短語將用於本地日記的加密及解密。
- 即使輸入錯誤的密碼短語，應用程式本身亦不一定會始終完全鎖定；在某些情況下，會表現為部分日記內容無法讀取。
- 部分日記可能會根據建立時或暫時解除鎖定時所使用的密碼短語而另行加密。

使用者應妥善保管密碼短語；如遺失，部分本地資料可能難以恢復。

## 9. 任務通知說明

當使用者啟用任務通知時，含有進行中任務的每篇日記都可能會排程本地通知。

- 通知排程主要透過裝置內部排程機制處理。
- 根據目前專案設定，未確認存在僅為通知目的而定期將日記原文傳送至中央伺服器的架構。

## 10. 權限使用說明

本應用程式可能使用以下權限以提供相關功能：

- `INTERNET`：與 Firebase、OpenAI 及廣告 SDK 通訊
- `com.google.android.gms.permission.AD_ID`：使用廣告識別碼
- `POST_NOTIFICATIONS`：顯示任務通知
- `RECEIVE_BOOT_COMPLETED`：於裝置重新開機後還原已排程通知

相關權限僅於執行對應功能所必需的範圍內使用。
